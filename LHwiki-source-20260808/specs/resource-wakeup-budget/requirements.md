# 资源唤醒治理需求

## 目标

- 空闲写作不得访问 PostgreSQL；公开浏览只允许在六小时缓存未命中时，以一个函数激活并行读取公开白名单字段。
- 云端草稿仅由“立即保存”和“提交审核”等明确动作触发，禁止计时器、联网事件、失败重试或页面离开触发云端写入。
- 投稿、退回修改、审核、发布、权限管理与本机恢复能力保持完整。
- 普通学号扫描不得被逐请求放大为数据库读取；个人中心应一次函数调用返回草稿、文章投稿和教师补充。
- 以 2026-09-01 至 2026-09-06 的维护期作为低消耗基线。上线后 24 小时的资源点增长不得高于该基线日均的 5 倍；超出即回到资源保护维护并排查。

## 可验证验收条件

1. 空闲编辑只写 `localStorage`，网络 API 调用数为 0。
2. 不存在云端草稿时，首次手动保存只发送 1 个云函数请求。
3. 同一草稿键已存在而客户端没有 revision 时，不得静默覆盖，必须返回 409 冲突；已知 revision 的更新继续使用乐观锁。
4. 旧于客户端协议 v4 的草稿写请求在鉴权或数据库访问前返回 409。
5. 访问统计前端不存在上传代码，兼容 API 永久返回 `paused: true` 且不访问数据库。
6. 普通学生在同一函数实例内登入后，`/api/session` 不产生用户表查询；权限操作仍实时核验。
7. “我的投稿”只请求 `/api/mine` 一次，返回三个原有列表。
8. 审核批准后，强制刷新可立即从 PostgreSQL 读取新公开内容；普通访客最迟在六小时缓存到期后看到更新，数据库失败时回退部署快照。
9. 完整自动化测试通过；发布前重新同步、备份并按函数后静态前端的顺序部署。

## 非目标

- 不改变网站视觉、编辑器排版或审核规则。
- 不修改数据库结构、历史迁移或生产权限配置。
- 不在本次提交中部署生产环境。
