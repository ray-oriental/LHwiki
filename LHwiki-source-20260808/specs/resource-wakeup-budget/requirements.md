# 资源唤醒治理需求

## 目标

- 空闲写作、公开浏览和公开页面启动不得访问 PostgreSQL；公开内容只从对象存储快照或随版本发布的静态快照读取。
- 云端草稿仅由“立即保存”和“提交审核”等明确动作触发，禁止计时器、联网事件、失败重试或页面离开触发云端写入。
- 投稿、退回修改、审核、发布、权限管理与本机恢复能力保持完整。
- 普通学号登入、受保护管理员登入和签名会话恢复不得读取数据库；审核者或管理员真正执行私有操作时仍实时复核权限。
- 个人中心应一次函数调用返回草稿、文章投稿和教师补充。
- 每个计费周期以 3000 点为硬上限、2100 点为运行目标并保留 900 点安全余量；监控必须按实际周期长度和 PostgreSQL 五分钟计费桶估算，不能使用低于单次最小唤醒成本的日阈值。
- 最近开发、部署或备份活动应先与消耗时间对齐；只有安静时段仍出现数据库计费桶，或持续速度将导致周期超出预算时，才判定为运行异常。

## 可验证验收条件

1. 空闲编辑只写 `localStorage`，网络 API 调用数为 0。
2. 普通用户打开新写作页或恢复本机新草稿时不得请求 `/api/mine`；只有显式打开“我的投稿”或缺少本机内容的私有深链接才读取工作区。
3. 不存在云端草稿时，首次手动保存只发送 1 个云函数请求。
4. 同一草稿键已存在而客户端没有 revision 时，不得静默覆盖，必须返回 409 冲突；已知 revision 的更新继续使用乐观锁。
5. 旧于客户端协议 v4 的草稿写请求在鉴权或数据库访问前返回 409。
6. 访问统计前端不存在上传代码，兼容 API 永久返回 `paused: true` 且不访问数据库。
7. 普通学生和受保护管理员的登入与 `/api/session` 在任意函数实例中均不访问数据库；签名特权会话在实际私有操作入口实时核验。
8. “我的投稿”只请求 `/api/mine` 一次，返回三个原有列表，并在同一页面会话中复用结果直到私有写操作使其失效。
9. 审核批准后刷新并覆盖对象存储公开快照；公开访客读取该快照，读取失败时回退随版本发布的静态快照。
10. 监控脚本对新周期、一只计费桶、连续超速、恢复和安静时段异常唤醒均有确定性测试。
11. 完整自动化测试通过；发布前重新同步、备份并按函数后静态前端的顺序部署。

## 非目标

- 不改变网站视觉、编辑器排版或审核规则。
- 不修改数据库结构、历史迁移或生产权限配置。
- 不在本次提交中部署生产环境。
